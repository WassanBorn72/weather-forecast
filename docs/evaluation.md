# 精度検証と再現性

## 過去予報を取得

「データ管理」に管理トークンを入力する。Single RunsにはUTC初期化時刻（例：`2026-10-10T00:00`）を指定する。APIは秒なしのUTCを要求するが、アプリ内部はISO `Z`で統一。00/06/12/18 UTC・2026-04-02以降をMVPの取得対象にする。runが未提供なら通知する。

Previous RunsはUTCの対象期間（1回最大31日）と1〜7日前のオフセットを選ぶ。固定24/48/72/120/168hの診断に使い、短時間予報や特定の発表時刻の代替にしない。最新Forecast APIのpast_daysを過去予報と誤認して使用しない。

`forecast_runs.issue_time`は公式データに明示的な証跡がなければnull。Single Runsの`initialization_time`をそのまま代入しない。現在Forecast APIには発表時刻の情報がないので取得スナップショットを保存する。発表時刻が分かるproviderが追加された場合にもavailable_atを別に保持する。

## 実測を取り込む

観測APIにはNOAA NCEI Global Hourlyのアダプターを用意した。現在の環境では`www.ncei.noaa.gov`へのアクセスが拒否されており、実応答の照合は未完了。接続検証までは出典付き観測CSVを利用できる。再解析ERA5や最新モデルの値で実測を代替しない。

CSV例（形式だけの例で、実測ではない）：

```csv
observed_at,temperature,precipitation,humidity,windSpeed,windDirection,pressure
2026-10-11T12:00:00+09:00,22.1,0.0,65,2.3,180,1013.2
```

毎正時の観測を指定。温度℃、降水mm、風速m/s、風向°、湿度/雲量%、気圧hPa、日射W/m²、CAPE J/kg。降水は観測時刻までの1時間量であり、日積算や翌1時間量を混ぜない。湿度は観測された値をCSVに入力し、NOAAの場合は品質検査済み気温・露点から算出した値と出典に表示する。気圧は海面更正値。確率は実測ではないためCSVに入れられない。空欄をnullとして保存する。出典は機関・観測所ID・取得元URLを含める。

指定地点と観測所の位置・標高・風の測定高度の違いは検証結果に影響する。NOAAアダプターは応答座標と地点の距離が25km超なら拒否し、距離・観測所名を出典に保存する。気温0.1℃/風0.1m/sのISD倍率を適用、品質コード0/1/4/5以外と欠測符号を除外、毎正時以外は丸めず除外する。AA1〜AA4の降水は1時間量だけを使う。6時間量を6で割らない。

既存の同地点・同時刻の観測は上書きしない。訂正観測を扱う場合は今後revisionテーブルと公開時刻証跡を追加する。MVPはavailable_atを取り込み完了時刻とし、過去の観測が当時公開されたという証跡をユーザー入力から推測しない。このため遡及取り込みした観測によって過去の運用統合検証が一気に完成することはない。単独モデル診断や今後の統合学習には使える。

## 指標と重み

- 連続値：MAE、RMSE、Bias。風向は最短角度差。WMOコードは距離が意味を持たないため連続誤差を計算せず、統合は均等のカテゴリ投票。
- 降雨イベント：時間降水0.1mm以上。確率50%を分類閾値にAccuracy/Precision/Recall/F1。雨標本数・常時無降雨Accuracyを併記。無降雨期間のPrecision等の分母0はnull。
- 確率：0〜1のBrier Score、10ビンの校正表（実際の頻度・標本数）。欠測確率は計算から除外。降水量のBrierは0/1の決定論イベントに対する値で、確率予報とは区別する。
- 評価窓：過去7/30/90/365日。365日を選択しても足りないデータを補完しない。季節・地点・リード別に抽出。
- 運用重み：30日以内の標本に14日半減期、スケール（℃/m/sなど）で正規化した誤差の逆数。確率はBrierを使用。モデル間の共通時刻で20標本以上なら重み付き、そうでなければ均等。季節別の共通標本が20件未満なら季節横断。1モデルしかない変数はそのモデルの値を明示。
- 縮約：`w = 0.5/N + 0.5*q/sum(q)`。4モデルなら12.5〜62.5%、Nモデルならfloor `0.5/N`、ceiling `0.5+0.5/N`。重みの合計1。欠測モデルは時刻・変数ごとに除外。
- 運用予報は最寄りの参照リード（1/3/6/12/24/48/72/120/168h）の成績を使用し、そのリードを理由に明示。評価の保存予報・Single Runsは指定リード±1h、Previous RunsはAPIの固定オフセット。

## ベースライン比較

実運用バックテストは保存スナップショットのみ。各対象時刻のモデルが揃った最新の履歴を選び、全モデルが取得済みになった時刻をcutoffとする。学習にはcutoff以前に利用可能だった予報と観測だけを使い、予報対象自身や未来の観測を含めない。その後の同じ観測で、各単独/単純平均/精度ベース統合を比較する。各方式の標本数は一致する。

Single/Previous Runsの遡及取得は公開時刻の証跡がないためこの比較から除外し、単独診断だけを表示する。デモは合成データと明示した別系列で、実データDBには保存しない。

model_scoresには計算時刻・条件・指標・使用run ID・観測IDを保存。ensemble_forecastsには全入力の取得完了後の生成時刻・対象時刻・値・全変数の重み・変数ごとの信頼度・誤差目安・使用runを保存。運用重みは取得時刻基準のsnapshotだけで学習し、初期化基準・固定オフセットの履歴を混ぜない。UTC時刻とJSON値、コードバージョンを使い再計算可能。指標と統合の保存JSONにはalgorithmVersion=mvp-1を記録する。

## 現状の検証範囲

Open-Meteoの東京4モデルの現在予報・Single Runs・Previous RunsのHTTP取得を確認した。まだ正当な観測データと長期の運用履歴がないため、独自統合の実世界の精度向上は未検証。空の実データ評価は0標本、指標「—」になる。モデル比較と合成データでの計算検証は実際の優劣の証明ではない。
